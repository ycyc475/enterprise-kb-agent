# 当前系统手工功能测试清单

版本：M6人工测试第1轮；日期：2026-11-04，Asia/Shanghai。

本清单共 **104条**：普通页面/探索用例98条，技术辅助6条。全部初始为**未测**；此前自动化与开发代理评审结果不能代填本轮人工结果。当前功能范围见[功能清单与边界](当前系统功能清单与边界.md)。

## 怎么使用这份清单

1. 每批做10—15条。先完成第一批基础业务，再建测试沙盒，最后做会改变资料/规则/授权的测试。
2. P0是金额、权限、来源和核心链路；P1是管理完整性与体验；“探索”用于观察已知缺口及待确认范围；“技术辅助”没有条件就标阻塞。
3. 结果列改为“通过 / 失败 / 阻塞 / 建议”。失败保留用例ID、账号、问题原文、实际答案、引用、时间及截图；不要先删失败会话。
4. 回答可以换措辞。金额、单位、适用职级/城市、确认顺序、来源归属和权限必须满足预期；有引用按钮但摘录不支持结论仍是失败。
5. 任何越权、错算、编造企业制度或错误引用归属先记录并暂停相关测试；后续根据反馈修复，不通过修改预期或反复重问挑一次成功来判通过。
6. 普通聊天、上传和检索会产生少量模型费用；先做一次并留证即可。用量阈值不要靠真实消费到80/100元触发。

## 第一批建议顺序

第一批13条：BASE-01—03、AUTH-01—02、ASK-01—08。第二批13条：BUD-01—11、SEARCH-02—03。之后做CHAT-01—03。先用原演示账号，只需新建测试会话，不改原制度、规则或授权。每批完成即可反馈，再继续管理类测试。CHAT-02会保存测试会话条件，但不修改制度。

后续建议：AUTH-03建立测试账号 → KB-01/02准备授权 → DOC-01—04准备资料 → 其他文档/检索/问答 → RULE-01—08 → BUD-16和GAP-05 → CONS-01—05 → 账号/授权/界面等其余用例 → CONS-06及清理。规则编辑/暂停、撤权、停库、文档变更之后，先恢复前置状态再做后续用例。

## 变化类测试的恢复与收尾

1. GAP-05冲突文档、ASK-12注入样本在各自测试后删除，避免影响后续问答。
2. CONS-01失败替换不应切换当前版本；不要为了让空白文件重试成功而认定系统应修改原文件。
3. CONS-02成功替换后，先确认三个测试住宿规则暂停，再依次按v2对应行核对并恢复。**仅更改价格、未核对新来源不算恢复完成。**
4. CONS-04重新启库、CONS-05重新发布长期有效v2后，均需逐条人工核对恢复。费用恢复后重新计算，旧结果不会自动改成新价格。
5. 保留反馈截图和失败会话后，再按CONS-06删除自己的测试住宿文件。其他测试文档只删除带本轮前缀的副本；不删除四份正式虚构制度或M2原样例。
6. 暂停本轮创建的测试规则，停用两个测试知识库、三个测试账号；系统目前没有账号/知识库/规则删除页面，不要求硬删记录。
7. 从原企业公共制度授权中只移除本轮追加的测试账号，保留原成员；原employee_li/employee_wang资料与五条基线规则不应被本轮测试改变。
8. 最后复核原employee_li北京3天2晚仍为840、employee_wang为1240；确认公共住宿与补贴规则仍有效。若不一致，保留现场并反馈，不运行初始化脚本覆盖问题。
