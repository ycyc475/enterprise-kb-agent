## 产品定位与目标，已确认

面向求职、实习和作品展示，构建单企业、多用户的企业文档问答知识库 Agent。以国内差旅报销作为首版验证场景，展示文档管理、授权检索、跨文档分析、员工条件适配、费用复算与来源追溯的完整流程。

资料使用公开或自行编写的模拟文档。普通员工减少查找制度与整理办理步骤的工作；管理员维护资料、员工属性和规则。首版本机演示，使用外部模型 API。

## 核心用户故事

- 员工查询“出差前后需要完成哪些步骤”，系统综合多份有权限的制度并分别引用。
- 员工提出费用问题，系统带入模拟资料，澄清本次出差条件，匹配制度与规则，输出可核对的计算结果。
- 用户条件缺失、资料不充分或冲突无法判定时，系统明确提出问题或说明缺失依据。
- 复杂问题可触发授权范围内有限补查；达到上限时清楚说明已确认内容与未解决部分。
- 员工持续追问并管理自己的历史；管理员维护文档、资料和规则，系统反馈处理状态。

上述能力均已确认；具体回复模板、参数与异常细则仍待确认。

## 主要流程草案，建议方案

员工流程：登录 → 自动读取员工属性与授权范围 → 选择或确认提问范围 → 输入问题 → 澄清必要的出差条件 → 授权混合检索与有限补查 → 确认适用规则并计算 → 展示指南、费用明细与引用 → 继续追问或管理历史。

管理员流程：准备模拟账号与授权 → 维护员工资料 → 上传制度 → 查看处理结果并重试失败任务 → 依据条款录入规则 → 核对并启用规则 → 用固定用例验证 → 后续替换或删除资料并处理关联规则。

已确认身份、部门、职级以管理员资料为准；员工可修改本次目的地、天数、晚数。当前不采用对其他职级作假设测算的候选功能。

## 回答与引用

已确认：依据文档回答，跨文档整理，主动澄清，考虑当前有效制度，说明无法判定的冲突，展示引用片段、可靠位置和授权下载。

已确认估算口径为标准预算：住宿标准×晚数＋80元/天×出差天数。S1/S2 在北京、上海分别为300/500元每晚，在杭州、南京分别为200/350元每晚；出差1—30整数天，整数晚数满足0≤晚数<天数，未列明城市不自动归类。

已确认聊天为主，展示只读员工属性、可编辑本次条件卡、费用明细及引用抽屉；具体控件与视觉细节为实现设计。

PDF 引用可验证页码，Word/Markdown 使用章节或段落；无可靠位置时展示定位状态和引用片段。下载时验证当前身份与授权。完整预览与精确高亮为增强候选。

| 情况 | 建议行为 | 确认状态 |
| --- | --- | --- |

| 无文档依据、冲突无法判定 | 说明依据不足/冲突，展示允许访问的证据 | 原则已确认；模板待细化 |
| 员工属性与用户自述不一致 | 使用管理员资料，资料有误时引导管理员修正 | 已确认 |
| 文档更新导致规则失配 | 暂停受影响旧规则，管理员核对新条款后恢复 | 已确认；具体事务待设计 |
| 撤权或源文档删除 | 受影响历史回答/引用不可查看，排除后续模型上下文 | 已确认；版本替换和缓存细节待设计 |

| 文档解析失败 | 标明失败原因、允许重试，失败内容不参与当前问答 | 基础能力已确认；详细状态待设计 |
