# 当前系统功能清单与边界

核对日期：2026-11-19，Asia/Shanghai。基线：M6及问题分流/证据相关性修复。**已实现表示存在对应实现，不表示本轮人工测试已经通过。** 11月4日先盘点并准备测试；11月19日用户明确授权修复模型身份误答，详见[修复与复测记录](../问题分流与证据相关性修复记录.md)。

系统目前是一套围绕企业文档与国内差旅制度的知识助手，使用Qwen对话、RAG混合检索和LangChain工具调用。当前对话配置为qwen3.7-flash，向量配置为text-embedding-v4/1024维。明确的模型身份、助手能力、上传帮助、预算确认说明和问候已有独立分流；混合提问分别处理。

## 已实现的功能

| 模块 | 当前可以做什么 | 可见入口 / 重要边界 |
| --- | --- | --- |
| 登录与会话 | 账号密码登录、退出、刷新页面恢复登录、登录失效处理 | `/login`；访问令牌在浏览器内存，刷新凭据使用HttpOnly Cookie |
| 密码与账号 | 首次临时密码强制修改、用户改密、管理员建号/重置密码/启停/切换角色 | `/account`、`/admin/users`；管理员不能停用或降级自己；没有员工自注册和账号删除页面 |
| 员工资料 | 查看本人姓名/部门/职级，管理员编辑资料并检查版本冲突 | `/account`、`/admin/profiles`；员工不能靠自述或改表单升级职级 |
| 知识库管理 | 创建、编辑、启停知识库，按用户授权 | `/admin/knowledge-bases`；当前没有知识库删除功能；权限以知识库为单位 |
| 文档入库 | 上传Markdown、文字PDF、DOCX，异步解析/分块/向量化、进度及失败提示、失败重试 | `/knowledge`；管理员上传，员工查询下载；不支持扫描OCR和复杂图表 |
| 文档生命周期 | 核对片段、设置生效/失效时间、替换版本、删除 | 新版成功后发布；失败不会覆盖仍有效旧版；删除为逻辑删除，不是物理擦除 |
| RAG检索 | 关键词与向量混合检索，按授权、当前版本及生效状态筛选 | `/knowledge`的“检索文档”；有相近片段不等于已经回答了问题 |
| 引用与下载 | 回答引用、文档标题/版本/位置/摘录、授权下载原文件 | 聊天引用按钮、文档来源抽屉；MD行号，PDF页码，DOCX段落/表格位置 |
| 个人对话 | 新建、重命名、删除会话，多轮上下文、刷新后查看历史、切换会话范围、取消运行 | `/`、`/chat/:id`；所有角色只读自己的对话，管理员也没有查看他人私聊权限 |
| 文档问答 | 标准查询、跨文档流程整理、基于授权研发资料回答、缺资料时拒绝编造 | 正常制度回答应有支持结论的真实引用；不支持“任何问题都回答” |
| 系统介绍与帮助 | 模型型号从本轮配置读取，助手能力/上传方法/确认原因/问候由程序提供 | 明确的完整问句走独立分支，不检索、不调用模型、不附文档引用；含企业问题时保留RAG部分 |
| 回答证据核验 | 文档类候选答案增加独立模型核验，区分引用不相关和结论不受支持 | 核验调用单列用量并共享10次/90秒/预算限制；失败不发布未经核验的候选结论；不替代人工验收 |
| 受控Agent | 调用补充检索、本人资料、出差条件提议、程序预算四类工具，展示运行进度与计数 | 每轮最多5次检索、10次对话模型请求、90秒；不是任意命令执行或多Agent协作 |
| 行程条件 | 自然语言提取目的地/天数/晚数，待确认卡、手动修正及保存 | 不自动从天数推断晚数；明确整数天/晚和常见中文数字可核验；复杂日期/多目的地不在当前范围 |
| 标准预算 | 员工确认后按权威职级和有效规则计算住宿＋日补贴，可直接填条件卡计算 | 单价来自规则，Decimal计算到分；直接计算不调用模型；不等于实际支出或审批金额 |
| 费用规则 | 新建/编辑草稿、绑定真实来源摘录、人工核对启用、暂停、重叠规则拦截 | `/admin/fee-rules`；没有规则删除功能；编辑会退回草稿，规则重叠按全系统范围检查 |
| 更新核对恢复 | 来源变化/失效导致规则不可用，查看旧/新条款，逐条核对恢复 | 文档“关联规则”、费用规则“核对恢复”；重新启用知识库不自动恢复规则 |
| 历史依据保护 | 撤权、删除、替换、到期、规则修订后，对受影响历史答案/引用/预算做遮蔽 | 旧答案不会自动按新标准重算；需要重新提问/确认计算；不要求用户自己删除旧记录来防泄露 |
| 管理操作历史 | 文档、规则、授权、账号/员工资料变更摘要，按对象查看、筛选/分页 | `/admin/audit`及对象历史；不记录聊天正文、密码、Key；没有历史修改/删除接口 |
| 用量与保护 | 估算用量、模型/用途/状态明细、未知费用预留、80元提醒/100元暂停新付费请求 | `/admin/usage`；应用估算不等于服务商账单，不提供充值或服务商账单管理 |
| 页面交互 | 中文输入、空输入限制、处理中状态、重复提交保护、错误提示、窄屏适配 | 在浏览器中人工检验真实可用性；并非所有可访问性/网络场景都已经由人工覆盖 |

## 当前演示制度与标准

四份正式虚构制度为住宿标准、差旅补贴、报销材料与办理流程、研发项目差旅归档。M2三份技术样例另用于格式展示，不能覆盖正式虚构制度。

| 城市 | S1住宿标准 | S2住宿标准 |
| --- | --- | --- |
| 北京、上海 | 300元/晚 | 500元/晚 |
| 杭州、南京 | 200元/晚 | 350元/晚 |

补贴统一80元/天。天数1—30整数，晚数0—29整数且小于天数；不自动把广州等城市归类。“北京市”也不应在未约定别名的情况下直接作为“北京”套价。

演示账号基线：`employee_li`为S1、产品部、仅公共制度；`employee_wang`为S2、研发部、公共制度＋研发资料；`admin`管理系统。密码只在本机凭据文件查看。若此前已经人工修改过这些资料，先记录实际配置，不能直接照搬旧基线认定失败。

## 已知缺口、实现边界与未实现事项

| 项目 | 当前事实 | 本轮怎样记录 |
| --- | --- | --- |
| 模型身份问题 | 已按用户授权修复；本轮型号读取任务配置快照，不受企业文档影响 | 原失败截图保留，按GAP-01重新手测；旧回答不自动改写 |
| 问候与系统能力介绍 | 已有保守规则分流；包含“模型”的企业制度问题仍走RAG，模糊表达可能需澄清 | 按GAP-02/03及专项清单测试；不是开放聊天功能 |
| 开放常识/创作/联网 | 当前只允许授权证据及本人资料等既定依据，不是开放聊天或联网搜索产品 | 是否加入属于待确认范围，不预先认定所有拒答都是故障 |
| 引用语义正确性 | 程序检查来源/摘录/权限，文档类答案再由独立模型调用检查相关性及支持性；模型判断仍可能出错 | 人工逐项比较结论与原文，不能只数引用按钮，也不能把模型核验等同人工签字 |
| 规则单价核对 | 检查摘录属于来源，不会自动理解任意原文并证明填写价格与条款完全一致 | 管理员必须核对价格、职级、城市、单位和来源行 |
| 文本冲突与规则冲突 | 结构化规则重叠有拦截；未启用为规则的相反文档不会被计算器自动全文语义裁决 | 分别测试纯问答和预算，记录差异再确定改进策略 |
| 不支持内容 | OCR、复杂合并表格/图表、历史日期政策匹配、多目的地预算、实际票据核验/审批、外部业务写入、多企业、生产部署 | 说明边界；不能把尚未实现内容当作本轮已交付功能 |
