# M5 管理一致性与操作历史开发及验收记录

日期：2026-11-04（Asia/Shanghai）

## 已确认范围与交付

用户授权继续M5，并明确选择：记录文档、费用规则、知识库授权以及账号/员工资料的管理变更摘要；仅管理员可查看，不记录员工聊天内容、密码或API Key。原有私聊权限不变，管理员不能通过操作历史或其他接口读取员工会话。

本阶段完成“制度更新→关联规则暂停→核对当前条款与单价→恢复单条规则→重新计算”的管理流程，新增管理操作历史、预算用量明细及相应的权限/一致性验证。M1—M4功能继续可用；最终固定40例业务验收仍留在M6。

## 文档与规则更新闭环

管理员可在文档列表进入“关联规则”，按当前文档筛选费用规则；规则表显示待处理数量、来源失效原因，并可打开规则/文档各自的操作历史。

1. 提交替换文档后，旧版在仍有效的前提下继续工作，等待新文件处理结果。
2. 解析、向量化和索引全部成功，才发布新当前版本；在同一事务中暂停引用旧版本的已启用规则并递增revision，记录文档发布及规则暂停事件。
3. 替换失败不发布半成品，不暂停仍有效旧规则，保留失败和重试记录。
4. 管理员进入“核对恢复”，并排查看原依据和同一文档的当前有效片段；明确选择新片段、核对摘录和单价，勾选核对后确认。
5. 服务端复核规则revision、预期来源版本、片段归属/有效性、摘录、权限和范围冲突；一次事务完成新来源/单价/核对者写入、规则启用及变更记录。
6. 每条关联规则分别核对恢复。未处理规则继续暂停，其他未受影响规则仍可使用；旧预算不自动更新，应重新计算。

恢复入口保留原规则的名称、费用类型、职级和城市范围，只重新确认来源与单价。如需改适用范围或关联其他文档，使用原有“编辑→草稿→核对启用”流程。来源已删除、到期、未生效或KB停用时，恢复入口说明原因，不绕过当前有效性检查。

恢复提交缺少核对、使用旧片段/错误版本、关联其他逻辑文档、伪造摘录或revision落后时均拒绝，不留下成功恢复记录；变更记录写入失败也会回滚业务变更。

## 权限、有效期和历史

- 删除来源文档：同一事务暂停关联已启用规则，后续检索、下载和历史读取继续统一校验。
- 停用知识库：暂停该KB的已启用规则并记录原因。重新启用KB不自动恢复计算规则，须核对后手动启用/恢复。
- 撤销某位员工授权：只改变该员工当前可访问内容，不全局暂停其他员工仍能使用的规则；受影响回答、预算和引用不返回，也不进入后续模型上下文。
- 来源到期/索引配置变化：计算和历史读取立即按当前状态阻断；文档worker约每5秒检查一次已启用规则，把失效原因和暂停状态补记到历史。worker处理作业时，状态补记可能稍后发生，不将该周期声称为硬时延保证。
- 规则编辑/暂停/revision变化：继续采用M4的保守整条预算隐藏策略；原快照保留，读取API不返回旧正文、结构化金额或引用。恢复后也不会把旧revision的预算重新当成有效结果。
- 账号角色/启停、管理员重置密码、员工资料revision变化：沿用已实现的登录撤销和运行复核机制，并新增相应管理变更记录。

测试同时检查消息、预算详情、引用和下载，防止只在界面隐藏而其他接口仍能读取。已显示过的文字无法从用户记忆或截图中撤回；未新增实时撤回推送。

## 操作历史

新增`audit_events`表，累计21张业务表。以递增BIGINT作为分页序号，保存管理对象类型/UUID、动作、操作者ID/账号快照、时间和变更前后摘要；成功管理动作与记录在同一事务提交。worker自动处理标记为“系统处理”，不冒充管理员亲自操作。

记录范围：

| 对象 | 记录的动作 |
| --- | --- |
| 费用规则 | 创建草稿、编辑退回草稿、启用、暂停、来源失效暂停、核对新来源恢复 |
| 文档 | 上传、提交替换、处理发布、处理失败、失败重试、删除；重启中断按失败原因记录 |
| 知识库 | 创建、修改/启停、成员授权；摘要保留授权账号名单 |
| 账号 | 创建、角色/启停变更、管理员重置密码及登录版本变化 |
| 员工资料 | 姓名、部门、职级、revision变化 |

只保存白名单字段，凭据、密码哈希、令牌、环境配置和员工聊天不进入记录；文档不保存原始文件路径或完整正文，规则保留管理员已录入的依据摘录。规则单价按两位小数字符串记录，避免浮点改变金额。

迁移`0005_m5`为当时已有的五条规则写入“迁移时的规则基线”。这是迁移时现状，**不补造M1—M4的操作过程**，也不假称历史记录自项目开始就完整存在。

应用不提供历史的新增/修改/删除接口；数据库触发器拒绝普通UPDATE/DELETE。它不等于外部不可篡改存证，拥有数据库结构管理权限的人员仍能改变结构或触发器；备份、保留期限和外部审计存储不在本阶段扩展范围内。独立测试库的TRUNCATE用于测试隔离，不作用于应用库。

页面`/admin/audit`按对象/动作筛选，序号游标加载更早记录，可看变更前后明细；时间按Asia/Shanghai显示。规则和文档行内可打开各自历史，避免混入其他对象。非管理员接口返回403，管理员私聊边界没有扩大。

## 用量与预算保护

新增`/admin/usage`管理页面，展示累计模型估算、未知/在途预留、80/100元阈值以及按模型/操作/状态分组的记录数和已知输入/输出Token。费用为应用估算，实际扣费与服务商额度以百炼账单为准。

保护行为不放宽：付费请求先在共享数据库锁内预留；累计达到提醒线显示提醒，本次预留若将超过100元则拒绝。失败或用量未知的记录保留预留，不伪造零费用释放。即使模型预算暂停，直接条件卡程序计算仍可使用。页面不提供清零计数或绕过保护的按钮。

相同KB授权、账号和预算保护采用既有服务，没有新增模型或切换默认型号；继续使用百炼qwen3.7-flash及text-embedding-v4/1024。

## API 与代码

统一`/api/v1`前缀，以下新增接口均需当前管理员身份：

| 方法 | 路径 | 主要契约 |
| --- | --- | --- |
| GET | /admin/audit-events | entity_type/entity_id/action筛选，before_id序号游标，limit默认50、最大100 |
| GET | /admin/fee-rules/{id}/source-review | 原规则、旧依据、当前有效版本和片段候选；仅用于管理员核对 |

主要实现：`services/audit.py`、`api/audit.py`、fees恢复/核对/失效检查、文档和管理服务事务记录、`AuditHistory.vue`、`AuditLogView.vue`、`UsageView.vue`及规则/文档入口。数据库变更走`0005_m5`迁移，业务进程仍使用非超级用户kb_app。
