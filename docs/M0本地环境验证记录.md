## 问题与处理

- Docker CLI启动最初因缺少安装注册项失败，直接启动也未连通；用户手动启动Desktop后引擎和项目容器验证通过。
- 受限网络环境阻止PyPI/npm下载及本地Docker管道，获准本机访问后完成项目内安装与检查。
- 受限环境中的ASGI探针挂起；停止该探针后，在本机权限下45秒超时约束内约5秒完成全部依赖检查。
- TypeScript7的包入口不再提供本探针/工具使用的传统编译API；调整为6.0.3后，构建和Vue类型检查通过。未把安装成功当作兼容性通过。
- jieba在Python3.13首次导入出现第三方转义语法警告；分词检查通过。解析质量和长期替代选择留待实际资料评测，不改第三方包源码。
- Windows下Psycopg异步连接需要Selector事件循环；探针显式创建局部Selector运行器，后续异步服务启动须采用匹配配置，不修改用户全局策略。[Psycopg说明](https://www.psycopg.org/psycopg3/docs/advanced/async.html)

## 镜像与本机配置

数据库镜像摘要记录在infra/image-lock.json，Compose和.env.example使用该摘要。当前项目容器保持运行，使用独立数据卷；没有停止其他容器或删除数据卷。

.env由bootstrap脚本生成本机数据库/JWT随机密钥并加入忽略；未在输出或设计文档中暴露凭据。模型Key保持未配置状态，MODEL_TESTS_ENABLED=false。当前数据库初始化账号用于M0；M1需建立应用角色及相应迁移权限。

## 复现命令

在项目根目录使用已具备依赖的本机终端：

```powershell
python scripts/bootstrap_m0.py
docker compose --env-file .env -f infra/compose.yaml up -d --wait
& backend/.venv/Scripts/python.exe scripts/m0_backend_probe.py --phase dependencies
& backend/.venv/Scripts/python.exe scripts/m0_backend_probe.py --phase database
node scripts/m0_frontend_probe.mjs
```

首次恢复环境先按锁文件同步依赖（uv sync --project backend --locked --no-install-project；npm ci --prefix frontend --ignore-scripts）。受限代理环境下可能需要相应本机访问权限。
