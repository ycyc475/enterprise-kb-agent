## 实现默认值与边界

以下属于本次落地的工程默认值，未将它们改写为用户已单独确认的业务需求：

- 访问 JWT 默认 15 分钟，仅保存在页面内存；刷新族绝对有效期 7 天，轮换不延长绝对期限。令牌包含 `sub/sid/jti/ver/iat/exp/iss/aud`，不使用前端或 JWT 中的角色/KB 列表作为权限真值。
- Cookie 路径 `/api/v1/auth`，`HttpOnly`、`SameSite=Lax`；本机 HTTP 下 `COOKIE_SECURE=false`。当前服务仅绑定 `127.0.0.1`，不是生产部署配置。
- 登录检查 Origin；刷新、退出同时检查 Origin 和 `X-CSRF-Token`。匿名 `GET /auth/csrf` 返回 `csrf_token: null`；有效上下文返回供刷新/退出使用的值。
- 前端用 Web Locks 串行化同源多标签页的 Cookie 认证操作，并对并发刷新使用同一 Promise；浏览器需支持该 API，已在本机 Edge 验证。
- 新密码长度 12—128 个字符；新建和重置账号随机生成临时密码，只在当次管理响应/弹窗展示。当前管理员不能禁用、降级或重置自己的账号；本人改密走个人资料页。
- 管理操作串行化安全变更，刷新按 user→family→token 顺序锁行，避免消费同一个刷新令牌或并发管理造成锁定。
- 授权和知识库共用 KB revision；编辑资料和授权变更提交预期版本，冲突时刷新后重新编辑。
- 当前成员与知识库列表返回 `items/total`，没有游标分页；面向本地小规模演示。未实现账号删除、自注册、密码找回邮件、生产限流、SSO 和会话清理任务。
- 撤权后新 API 请求立即按当前授权判断；已打开的知识库摘要通过页面刷新按钮更新，不包含尚未实现的文档/历史内容。后续文档、引用和会话接口仍必须分别接入授权检查。

## 可复现验证

先按 README 启动 Docker、初始化数据库并安装依赖。

```powershell
Push-Location backend
.venv/Scripts/ruff.exe check app migrations tests
.venv/Scripts/python.exe -m pytest tests -q
Pop-Location
Push-Location frontend
npm.cmd run build
npm.cmd run test:e2e
Pop-Location
```

后端测试自动创建 `enterprise_kb_test_<随机值>` 独立数据库，并在 finally 中删除。清理前校验固定前缀与随机格式，禁止清理应用数据库。创建测试库需要 `.env` 的本机 bootstrap 账号；业务服务不使用此高权限账号。

浏览器测试使用已有演示账号，不输出密码，不采集包含登录请求的 trace；撤权测试在 finally 中恢复原授权集合，但 KB revision 会正常递增。浏览器报告和无密码页面截图位于忽略提交的 `.m1/`。运行前应保留初始演示账号与知识库名称。

- 前端严格类型检查与生产构建通过；后端 Ruff 检查通过。
- 本机已验证 PostgreSQL 数据持久化、后端健康检查及前端入口。固定 40 例为后续完整业务验收，本次未执行，不计入上述测试数量。
