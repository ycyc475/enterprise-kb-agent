# 运行与展示指南

适用版本：M6 / API 0.6.0，Windows本机演示。完整安装步骤见[README](../README.md)，环境配置见 `.env.example`。密钥只填本机 `.env`，密码只查看本机 `data/runtime/demo-credentials.json`，均不要提交或放入演示视频。

## 启动和日常检查

保持Docker Desktop启动，在项目根目录运行：

```powershell
docker compose --env-file .env -f infra/compose.yaml up -d --wait
./scripts/start.ps1
Invoke-RestMethod http://127.0.0.1:8000/health
```

访问 [工作台](http://127.0.0.1:5173) 和 [接口文档](http://127.0.0.1:8000/docs)。统一使用127.0.0.1，避免与localhost来回切换造成Cookie不共享。修改Python代码或 `.env` 后执行 `./scripts/stop.ps1`、`./scripts/start.ps1`；停止脚本只停止本项目应用，不删除数据或关闭数据库。

本机已迁移至0006_expenses，导入新综合费用制度并启用八条规则，默认限制5/10/180。刷新后新建会话，范围包含“企业公共制度”，按[本轮清单](测试/综合费用与问答修复手工测试-2026-11-19.md)复测。旧M6验证脚本检查原冻结资料，不适用于当前资料集合，日常启动无需运行，也不要重新执行旧种子脚本恢复已删除文档。

以下保留M6历史复现步骤（当时迁移0005_m5），不适用于覆盖当前资料；操作可能产生模型费用：

```powershell
backend/.venv/Scripts/python.exe scripts/m2_live_smoke.py --live
backend/.venv/Scripts/python.exe scripts/m6_seed_demo.py --live
```

M6脚本发布四份已冻结的虚构制度，创建/恢复五条演示规则；只允许识别出的M4原文升级，不覆盖未知用户修改。规则基线为北京/上海S1 300、S2 500；杭州/南京S1 200、S2 350；补贴80元/天。

## 展示顺序

| 步骤 | 操作 | 应展示的价值 |
| --- | --- | --- |
| 1 | employee_li登录，问“根据虚构演示制度，从申请到报销需要哪些步骤？” | 出行前批准、保存资料、返回后人工审核，分别查看引用 |
| 2 | 问“我去北京出差3天，住宿2晚，请估算住宿和补贴预算” | 先出现待确认卡；确认前没有预算金额 |
| 3 | 核对并确认 | S1，600住宿＋240补贴＝840；价格来自有效规则，程序计算 |
| 4 | 打开引用，下载原文 | 标题、版本、条款行号及授权下载 |
| 5 | 问“改成杭州，其他不变”，再确认 | 保留3天2晚，改为640元 |
| 6 | 新会话问“去北京三天，完整预算？” | 晚数仍待补充，不自动填两晚 |
| 7 | 换employee_wang，问研发额外归档要求 | 可见项目编号和工作记录；employee_li无该限定资料权限 |
| 8 | admin查看规则、文档、操作历史与用量 | 核对恢复、摘要历史和预算保护；管理员不能看别人私聊 |

本机演示录屏位于 `.m6/demo.webm`，约29秒，无配音；它展示上述前四步及移动布局。自动化录制的等待时间来自真实模型请求。手动演示可按表逐项说明，不必追求视频中的速度。

制度更新演示会暂停规则并隐藏旧答案，正式展示前保留基线。可直接观看已验证的更新恢复截图/测试结果；如要现场更改，明确使用虚构素材，完成后恢复原文并逐条核对恢复，不能只改价格后跳过来源检查。

## 验证命令

后端119项使用独立测试数据库，不调用外部模型：

```powershell
Push-Location backend
.venv/Scripts/ruff.exe check app migrations tests
.venv/Scripts/python.exe -m pytest tests -q -p no:cacheprovider --basetemp=../.m6/tmp-local
Pop-Location
Push-Location frontend
npm.cmd run build
Pop-Location
```

只运行固定确定性20例：进入 `backend` 后运行 `.venv/Scripts/python.exe -m pytest tests/test_m6.py -q -p no:cacheprovider --basetemp=../.m6/tmp-fixed`。需要本机Docker数据库。pytest只允许自动创建并删除指定前缀的随机测试库，不对应用数据库做清空。

再次运行真实问答会付费，并产生新的待评审输出，不自动覆盖既有逐题评审结论：

```powershell
backend/.venv/Scripts/python.exe scripts/m6_evaluate.py --live
# 仅复测相关题目示例
backend/.venv/Scripts/python.exe scripts/m6_evaluate.py --live --cases 'QA10 or QA11'
```

脚本先预留1元，隔离库也限制1元；结束后将每条用量幂等导回主账本，报告在 `.m6/evaluations/<运行ID>/`。中断且未导出用量时，总预留保守保留；不要手工把未知费用改成0。重新评测的 `.m6/qa-results.json` 仅是运行和基础诊断，需要逐题检查实际答案/引文后才能形成新的验收结论；当前已审阅结果是 `.m6/qa-final.json`。

浏览器14条测试会调用真实模型并临时改变授权/演示制度，结束时恢复。录屏依赖官方FFmpeg，安装到项目缓存：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH=Join-Path (Get-Location) '.cache/ms-playwright'
Push-Location frontend
npx.cmd playwright install ffmpeg
npm.cmd run test:e2e
Pop-Location
```

测试失败或进程中断时先检查报告，避免连续重跑产生不必要费用。授权检查点会在测试前后核对恢复，遇到外部修改拒绝覆盖；M5来源变更检查点可用 `backend/.venv/Scripts/python.exe scripts/m5_restore_demo.py --restore` 显式恢复该已保存测试目标。当前展示状态以M6验证脚本和冻结文件哈希为准。

## 常见情况

- 无模型回答：检查本机Key、同地域Base URL、模型权限、服务商额度和管理员用量页；修改配置后重启应用。不要把Key发到聊天里。
- 上传失败：先查看具体原因；首版不支持扫描OCR、加密/损坏文件和复杂图表，失败新版不会覆盖仍有效旧版。
- 新版已发布但不能完整估算：受影响规则暂停是预期保护；管理员在来源核对页面核对新条款、单价后逐条恢复。
- 历史答案显示依据不可用：检查撤权、文档删除/替换/到期和规则版本变化，不能通过旧运行或引用接口绕过。
- 验证脚本报告状态不符：它会检查本机固定演示基线和保存的测试证据；日常自行新增文档或修改规则后不一定匹配原验收快照，不要为通过脚本覆盖自己的业务修改。
