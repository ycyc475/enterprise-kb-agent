## Q1：费用口径候选

已确认 A：按制度标准估算本次差旅的住宿预算额度与补贴，输出“按标准估算金额”。

- 住宿预算额度 = 适用的每晚住宿标准 × 住宿晚数。
- 补贴估算 = 每日补贴标准 × 补贴计费天数。
- 合计估算 = 住宿预算额度 + 补贴估算。
- 不读取票据或实际支付数据；具体支出与财务审批属于其他业务口径。

方案 B：增加用户输入的计划每晚价格，分别展示预计支出与按制度可覆盖的估算金额；需要额外确认超标部分、封顶和输出标签。

当前采用 A，下列用例据此复算；B 仅保留为历史比较。

## Q4：制度替换与费用规则一致性候选

已确认 A：新文档处理成功后生效，旧版本退出当前检索；引用被替换条款的费用规则暂停，管理员核对新条款并确认关联后恢复估算。期间仍可回答有依据的问题，并明确金额暂不可算。未受影响的规则继续可用。

方案 B：新文档与关联费用规则全部准备并核对好后整体生效；准备期间继续使用仍有效的旧版，保持估算连续性，但新增成组发布流程。

两种方案都建议：处理失败不发布不完整内容；已失效旧版不能因处理失败而继续充当当前制度。规则依据被删除、无权访问或无法确认有效性时，暂停受影响金额计算。

## Q5：撤权、删除与历史候选

已确认 A：按当前权限与资料可用状态读取历史。撤权或源文档删除后，受影响的历史回答和引用显示不可用占位，完整内容不再从接口返回，也不进入后续模型上下文；下载重新校验授权。其余会话操作仍可进行。

方案 B：保留已生成回答文字，失效引用标注不可用，新检索与下载按当前权限执行。回顾连续性更好，但撤权后的旧文字仍可能被阅读。

对于单纯版本替换，建议历史标记“引用旧版本，当前制度已更新”，新问题重新检索当前依据；具体展示和上下文规则仍需确认。限制删除/撤权与版本替换分别记录。
